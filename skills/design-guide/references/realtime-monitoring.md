# Realtime Monitoring

Use this component when recent movement and current health must be readable together: CPU, memory, network traffic, queue depth, or periodically checked service status. The [Realtime Monitoring example](../assets/component-reference/index.html#realtime-monitor) stacks three resource presentations—sparkline, heat strip, and arc gauge—followed by a separate service-timeline example. All four receive the same timestamped snapshots. Use either resource or service groups independently when the other adds no useful information.

## Anatomy and Appearance

- Keep the component transparent, borderless, and shadowless. Do not frame each resource in a card. Begin directly with the resource readings; omit the source/connection toolbar, standalone pause controls, demo controls, and status chips. Put source identity in the group's accessible name, and disclose simulated telemetry in that name and the inspection tooltip. Feed freshness describes delivery, independently of monitored service health.
- Use a resource grid with `repeat(auto-fit, minmax(min(100%, 156px), 1fr))`, 16px gaps, and no container padding. At 600px and below, use 12px column gaps. Let narrow containers collapse to a single column without widening the page.
- Center a 16px Lucide symbol over each current resource value, using `--muted`: `Cpu`, `MemoryStick`, `Download` for network in, and `Upload` for network out. Arc gauges use the larger symbol and positioning specified below. Omit visible resource-title text; retain the full name in a screen-reader label, icon title, plot name, and inspection tooltip. Use 26px, weight 700, line-height 1.1, tabular UI numerals, with a weight-400, 12px monospace unit at line-height 1. Align the number and unit on their baselines with a 5px gap; give sparkline and heat-strip readings 6px top and 4px bottom margins. Missing readings use an em dash without a unit; inspection and accessible text explicitly say `Unavailable`.
- Use the same data, freshness, and inspection rules across presentations. Each instance owns its own live buffer, frozen view, and selection; pausing or inspecting one catalog example does not affect the others.
- Fix metric scales at zero and a configured maximum. Do not rescale on every update. Classify a reading at or above `critical` as danger, otherwise at or above `warning` as caution, otherwise as good when either threshold exists. Without thresholds, use nominal styling. Current threshold breaches use `--caution` or `--danger` on the number at full opacity, paired with `Elevated` or `Critical` in the readout. In-range good numbers and their units use `--good` at 60% opacity; unthresholded numbers use `--muted`. Put the complete range, unit, and textual state in inspection and accessible text. A reading above the plot maximum retains its actual numeric value and says `Above scale` or `off scale` in inspection; clip only its plotted position.

### Sparklines

- Put a 64px SVG history directly below each reading, with no scale, state, or other text underneath. Match its view-box width to the rendered width and inset the zero and maximum positions 4px from the bottom and top. Draw a 1px `--line` baseline at zero; omit the plot background, outer border, standalone legend, and decorative grid. When a supplied warning is within the scale, draw it as a 1px `--caution` line at 45% opacity with a `3 4` dash pattern, and disclose its exact value in inspection and accessible text.
- Use a 1.5px trace with round joins and butt caps in every health tier. Color trace segments and area fills by each time interval's sample health tier, transitioning smoothly between adjacent sample midpoints (similar to heat strips). The current or inspected readout number and unit reflect the active sample's tier. An unavailable active reading uses nominal styling for any unthresholded history.
- Apply the dark cockpit treatment to thresholded traces: `--good` at 50% opacity and `--good-soft` area fill at 35% element opacity, `--caution` with `--caution-soft`, or `--danger` with `--danger-soft`. Caution and danger have no additional opacity reduction; area fills retain the alpha already defined in the soft tokens. Nominal styling uses `--accent` with `--accent-soft` for observed data, or `--derived` with `--derived-soft` for simulated data. Observed traces are solid; simulated or modeled traces retain a `4 2` dash pattern across all health tiers.
- Represent an isolated sample with a 2px-radius circle and an inspected sample with a 3px-radius circle. Use the corresponding trace color, with 55% opacity for good points and full opacity otherwise. These data markers keep their circular geometry across health tiers.

### Heat Strips

- Replace the 64px trace with 18px-high cells centered in a 24px-high SVG, leaving 3px above and below each cell. Center that SVG in a plot with a minimum 44px height. Draw one cell per sample at its elapsed-time position. Set the slot width to `max(1px, interval / windowMs × rendered SVG width)`, subtract a 1px gap when the slot is at least 3px wide, and keep the resulting cell width at least 0.5px. Leave unavailable metric samples unpainted; never fill a gap as zero. Do not draw a sparkline, area fill, or threshold hairline on a heat strip.
- Color metric cells by each sample's tier using `--good`, `--caution`, or `--danger`; nominal cells use `--accent`, or `--derived` when simulated. Good and nominal cells use `fill-opacity = 0.22 + 0.78 × clamp(value / max, 0, 1)`, rounded to two decimals. Good cells additionally have 45% element opacity, multiplying that fill opacity. Nominal cells have no additional reduction and can reach full opacity at the plot maximum. Caution and danger cells use full opacity. Keep all metric cells square.
- Service heat strips use the same 18px cells in the 24px SVG, with categorical `--good` / `--caution` / `--danger` / `--faint`. Use 45% opacity and 1.5px rounding for healthy cells; use full opacity for degraded cells with 1px rounding and for square danger or unknown cells. Do not apply numeric intensity scaling or merge service heat cells into variable-thickness bands.

### Arc Gauges

- Center a 132×132 dial in each resource card. Use center `(66, 66)`, radius 52px, and a clockwise 270° sweep from 135° to 405°, with 0° pointing right so the opening is at the bottom. Center a 24px symbol horizontally with its top 22px below the dial's top edge. Center the number/unit row vertically at the 66px midline with no margins. The dial is a current-value readout without a sparkline history below it.
- Draw an 8px `--line` track for the unread nominal sweep (stopping where threshold bands begin), then 8px threshold bands, then the reading fill. Drawing the track only across the unread nominal arc prevents the dark track from showing through the reading fill (matching the value text tone) or protruding behind threshold bands. Threshold bands have butt caps between zones: `--caution` at 60% opacity from warning to critical, and `--danger` at 80% opacity from critical to max. With only a warning, the caution band extends to max; with only a critical threshold, draw only the danger band from critical to max. With neither threshold, omit both bands. The terminal band reaching maximum caps with a rounded tip in its zone's color, leaving that end completely colored. Clip bands to the configured scale and omit a good background band.
- Fill from zero to the clipped reading with an 8px stroke: `--good` at 60% opacity, `--caution` or `--danger` at full opacity, or `--accent` / `--derived` at full opacity when unthresholded. The reading fill uses round caps; an unavailable or zero reading rounds the track start. Hide the fill when the reading is unavailable. Do not draw a needle line, tick line, or knob ball on the standard arc gauge. When peak hold is enabled (`peakHold: true`), draw a 2px square-capped `--ink-strong` tick line across radius 45px to 59px at the peak reading, immediately pushed up when readings rise, and decaying back down smoothly at 25% of `channel.max` per second when readings fall.

### Service Timelines and Catalog Layout

- When one instance contains both resources and services, place services 16px below resources. Use a service grid with `repeat(auto-fit, minmax(min(100%, 180px), 1fr))` and 12px gaps. This places the three example services side by side where they fit and stacks them on narrow screens. Put each service name directly above its full-width timeline, in 12px `--muted` UI text with a 20px line-height. Include both name and timeline in one button with a minimum 44px height. Allow long names to wrap. Omit left-side name columns and right-side status chips.
- In sparkline and arc presentations, render status history as continuous spans centered in a 24px-high plot, using the same timestamp scale for every service. Merge consecutive observations of the same state; do not draw individual dots, pills, tick marks, or a gap for every sample. Healthy spans are a quiet 3px good line at low-contrast 45% opacity with 1.5px rounding. Degraded spans are 6px caution bands with 1px rounding, outages are 8px square danger bands, and explicit unknown spans are neutral 1px lines. Pair thickness and color with complete state text in inspection and the plot's accessible name. Unknown data is not an outage.
- Omit all text and reserved readout space below the timelines, including the window duration and cadence. Keep these facts in the tooltip and accessible text, so they remain available without adding persistent chrome.
- In the component catalog, place demo simulation controls at the top of the section to adjust tick speed and severe event frequency without embedding controls into the reusable monitors. Mount resource-only instances under `Sparkline`, `Heat strip`, `Arc gauge`, and `Arc gauge with peak hold`, then one status-only instance under `Service timelines`. Use an `h3` for each example heading in 14px, weight 600, line-height 1.2, `--ink-strong` UI text. Separate examples by 40px and each heading from its mount by 12px. These headings and controls belong to the catalog wrapper, not the reusable monitor.

## Data and Freshness

- Take timestamped snapshots from the host application, not measurements scraped from the rendered DOM. Resource values and service states in one snapshot share its capture time. The host aligns asynchronous sources and sends `null` for unavailable channels; never carry a missing field forward as if it were freshly measured.
- Accept finite, nonnegative numeric measurements, including zero. Treat missing fields, nonnumeric values, negative values, and unrecognized service states as unavailable. Never coerce `null`, an empty string, or an unknown status into zero or healthy.
- Require strictly increasing epoch-millisecond timestamps at or before the supplied clock. Ignore duplicate, out-of-order, invalid, and future timestamps; they must not renew freshness. The host handles clock alignment and rates derived from counters, including counter resets and unit conversion.
- Bound both elapsed history and sample count. Defaults are a 60-second window, a 1-second expected cadence, and at most 600 snapshots. Draw positions from elapsed time, not array indexes. Break resource traces across missing values or intervals longer than 1.5 times the expected cadence. Never interpolate across a telemetry gap or generate catch-up samples after a suspended tab.
- Join adjacent status observations when their timestamps are at most 1.5 expected intervals apart, allowing ordinary sampling jitter. Otherwise end the previous state after one expected interval and leave the delivery gap blank. End the latest observed state after at most one interval; never extend a healthy state through a longer unobserved period. An explicit unknown observation forms a neutral span.
- Start with `Waiting for data`. An accepted snapshot restores the connected transport state; report `Live` while its capture age is below `staleAfter`, and `Stale` at or above that limit (three expected intervals by default). An already-old capture remains stale even if it has just arrived. Expose feed state and last-sample age in inspection and accessible text: repeated values can still be fresh, repeated timestamps cannot. Support explicit `Disconnected` and `Reconnecting` transport states. A `connected` notification alone must not make an old sample fresh.
- Retain last-known values when delivery stops, with their capture timestamp available in the tooltip, but do not label them current or replace service states with a fabricated outage. For `Stale` and `Disconnected` feeds, change the number/unit color to `--muted` while retaining its tier's opacity. Continue advancing the live time window so missing history is visible. Clear old plotted points when they leave the window. A reconnect resumes from new samples and preserves the intervening gap.

## Inspection and Updates

- On pointer movement over a resource or status history, snap to its nearest actual sample and immediately show a shared crosshair: a 1px `--ink` line with a `2 2` dash pattern at the same timestamp across the instance's histories. Keyboard focus uses the same inspection, choosing the latest available sample when no selection is active and preserving the selected timestamp when moving between channels while paused. Inspection changes the tooltip and history highlights; the large numbers and arc fills retain the latest shown readings.
- Use the [neutral tooltip appearance](overlays-and-feedback.md#9-tooltips-and-popovers) for the full UTC capture timestamp, channel name, value, unit/state, range, warning threshold, history duration, cadence, and feed freshness; disclose simulated data here. Plot inspection is an immediate data readout, so it is exempt from the general helper-tooltip restriction to icon-only or truncated triggers and the 150ms delay. Position it 8px above the inspected history, flipping below when necessary, and clamp it inside the viewport with 12px clearance. Use fixed positioning so it consumes no layout space, and attach `aria-describedby` only while the tooltip is visible. Clear unpinned inspection on pointer exit or blur; paused inspection remains visible.
- Make each interactive plot a native `button` with `type="button"`, full width, zero padding, transparent background, no border, square corners, a crosshair cursor, and `touch-action: pan-y`. Keep the shared focus-visible ring. These controls override the generic text-button appearance and use no press scaling. Click/tap or Enter/Space freezes the entire displayed time window and inspects the chosen sample; activating a plot again resumes. Left/Right and Home/End also pause and inspect, stopping at the available endpoints. Escape while a plot is focused resumes and dismisses inspection. Keep normal page shortcuts and vertical touch scrolling available; list these local keys in the catalog's shortcut popup.
- While paused, freeze readings, plotted data, and the window endpoint. Continue ingesting into the bounded live buffer. Keep the readout pinned on pointer exit or blur, allow inspection to move among the frozen samples, mark it `Paused`, and include an activation-to-resume hint alongside current feed freshness. Set `aria-pressed` on interactive plots to reflect the frozen view. Resume jumps directly to the newest window without replaying queued animation.
- Announce feed-state transitions and user-requested keyboard/activation readouts politely. Do not make the rapidly changing values, sample age, or whole component a live region. Give each plot an accessible name containing its channel, latest shown value, history duration, and warning threshold when present.
- Coalesce incoming snapshots to one render per animation frame; update freshness once per second even when delivery has stopped. Avoid animated scrolling, easing between readings, pulsing every update, and flash effects. Hidden tabs may defer rendering, but on return must compute freshness from elapsed time. No reduced-motion override is necessary for this nonanimated presentation.
- For a passive desktop readout, set `interactive: false`: omit inspection handlers, preserve resource symbols/current values and service names, and expose the histories as named images with freshness and units in their accessible names. Do not render inert web controls on a passive surface.

## Copy and Integration

Copy `components/realtime-monitor.css`, the shared tokens/base styles, and `components/tooltips.css`. Include the used Lucide symbols from `shared/icons.html` with their retained license, and load `shared/icons.js` before these classic scripts:

1. `components/realtime-monitor-model.js` — validation, bounded history, freshness, frozen views.
2. `components/realtime-monitor-plot.js` — resource traces, heat strips, arc dials, status geometry, shared crosshair.
3. `components/realtime-monitor.js` — DOM, controls, keyboard/pointer inspection, lifecycle.

The `realtime-monitor.html` fragment only provides the catalog section, simulation controls, and example mounts. `realtime-monitor-example.js` owns all fictional data; omit that script in applications. The component itself has no network, polling endpoint, Conky, catalog-ID, or framework dependency.

```js
const monitor = ComponentReference.createRealtimeMonitor(container, [
  { id: "cpu", kind: "metric", label: "CPU", icon: "cpu", unit: "%", max: 100,
    warning: 80, critical: 95, decimals: 0 },
  { id: "api", kind: "status", label: "API gateway" }
], {
  label: "node-01", interval: 1000, windowMs: 60000, staleAfter: 3000,
  maxSamples: 600, simulated: false, interactive: true, presentation: "sparkline"
});

// Call from your polling, WebSocket, or server-sent-event adapter.
monitor.push({ timestamp: Date.now(), values: { cpu: 42, api: "good" } });
// Use the actual capture timestamp from your source when it provides one.
monitor.setConnection("disconnected");
monitor.setConnection("connecting");
// A subsequently accepted snapshot restores the connected state.
```

Channel IDs must be unique. Metric channels require a unit and positive plot maximum, with optional precision from 0–6 decimals and finite, nonnegative warning/critical thresholds. Either threshold may be supplied independently; when both exist, require `critical >= warning`. The `icon` property names an included Lucide symbol in kebab case, defaulting to `activity`; retain `label` as the full accessible and tooltip name. Status channels accept `good`, `caution`, `danger`, or `null`, described as Operational, Degraded, Down, or Unavailable. The maximum is a plotting bound, not an automatically inferred capacity or alert threshold. `presentation` is `"sparkline"`, `"heatstrip"`, or `"arc"` and defaults to `"sparkline"`. Setting `peakHold: true` on an arc presentation renders a peak decay tick needle line pushed by the dial and decaying smoothly.

`push(snapshot)` returns whether the snapshot was accepted. `pause()`, `resume()`, `setInterval(interval)`, `reset()`, and `setConnection("connected" | "connecting" | "disconnected")` support host controls. An optional `clock` function supplies epoch milliseconds for deterministic testing; it defaults to `Date.now`. Repeated initialization of the same root returns its existing instance. Mount another root for another monitor. Call `destroy()` to stop its timer, observer, pending render, visibility and tooltip-position listeners, and remove its owned DOM; also close any subscriptions or timers owned by the host adapter. A destroyed instance ignores subsequent pushes.

Run the deterministic history/freshness checks with `node skills/design-guide/scripts/test_realtime_monitor.cjs` from the repository root. These cover data-model behavior and health-zone classification; they do not verify CSS, DOM interaction, or Markdown synchronization.
