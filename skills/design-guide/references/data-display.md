# Data Display

## 5. Labels, Badges, and Metadata

* Render status badges as inline-flex containers with 12px text, weight 500, line-height 1.2, 3px vertical padding, and 8px horizontal padding.
* Do not prepend a colored dot or reserve space for one. Put the complete status in visible text.
* Nominal badge: use `--surface-raised`, `--muted`, a 1px `--line` border, and pill radius.
* Good badge: use `--good-soft`, `--good`, a 30%-mixed good border, and pill radius.
* Caution badge: use `--caution-soft`, `--caution`, a 30%-mixed caution border, and 4px radius.
* Danger badge: use `--danger-soft`, `--danger`, a 30%-mixed danger border, and 0px radius.
* Derived badge: use `--derived-soft`, `--derived`, a 30%-mixed derived border, and pill radius.
* Apply a slow live-state pulse with a 1600ms `ease-in-out` cycle between the base soft background and a 28% current-color tint. Set iteration count to infinite.
* Apply a fast live-state flash with a 600ms `steps(1, end)` cycle between the same two backgrounds. Set iteration count to infinite and keep the rate below three flashes per second.
* Continue either animation while the represented state remains active. Remove the animation immediately when that state clears. Under `prefers-reduced-motion: reduce`, remove the animation and keep the same static text, color, border, and geometry.
* Render non-status tags, versions, and commit hashes in `--mono` at 12px with 2px vertical and 6px horizontal padding, 4px radius, `--surface-raised`, `--muted`, and a 1px `--line` border.
* When a metadata value such as an IP address, version, identifier, commit hash, or token is useful elsewhere, render it as a copyable native button. In a complete reference, make every non-status metadata example copyable. Preserve the plain metadata-tag treatment, give it a minimum 28px height and `cursor: copy`, and provide an action-specific accessible name such as `Copy IP address 192.168.1.104`; use a matching `title` only when the value does not need an expansion tooltip. Do not add a copy icon, and do not make status badges copyable.
* Display commit hashes in their compact seven-character form. On pointer hover and keyboard focus, reveal the exact full hash after 150ms in the neutral tooltip treatment; hide it on pointer exit, blur, or `Escape`, and connect it through `aria-describedby` only while visible. Keep the tooltip within the viewport. Copy the full hash rather than the compact visible label.
* Copy the exact underlying value on click, `Enter`, or `Space`. Prefer `navigator.clipboard.writeText` in a secure context and provide a selection-based fallback for non-secure local previews; preserve focus on the copy button when using the fallback. On success, keep the action-oriented accessible name, tag width, visible value, and 4px radius fixed; use only temporary neutral `--ink-strong` text and a `--line-strong` border for 1600ms, without a copy/check icon or green/good styling. Show one non-undoable success toast reading `Copied to clipboard`; rely on the toast stack's polite live region rather than adding a second inline live announcement. On failure, omit the success state and show a non-undoable danger toast reading `Could not copy to clipboard`.
* Do not place keyboard shortcut labels in badge or metadata rows.

## 6. Tables and Data Grids

* Wrap a table in a full-width region with horizontal overflow, a 6px radius, no outer border, and a transparent background. Keep the table and body cells transparent.
* Use semantic `<table>`, `<thead>`, `<tbody>`, `<th scope="col">`, and `<td>` elements. Supply a caption, visible or screen-reader-only, that names the dataset.
* Set table text to 13.5px and collapse borders. Use 10px vertical and 14px horizontal header padding and 12px vertical and 14px horizontal cell padding.
* Use 12px uppercase header text, weight 600, letter-spacing 0.04em, `--muted`, a transparent background, and a 1px `--line-strong` bottom border.
* Left-align prose and identifiers. Right-align numeric values, timestamps, currency, and measurements; use `font-variant-numeric: tabular-nums` and `--mono` for those cells. Align each header label to the same edge as its column's data.
* Separate body rows with a 1px `--line` bottom border and remove that border from the final row. Use `--surface-raised` on row hover, on the selected row, and while a control in the row has keyboard focus.
* When a row has a details view, make the row itself clickable and use `cursor: pointer`. Omit a separate `Action`, `Inspect`, or `View details` column. Preserve native table-row and cell semantics; put a native button styled as plain text in the primary cell, name it for the record's details action, and support `Enter` and `Space` through that button. Clicking a non-interactive part of the row opens the same view. Do not intercept nested controls or open details after the user selects text.
* Select and highlight the whole row when its primary button receives focus or the row is activated. Draw keyboard focus as a 2px `--focus` outline inset 2px around the entire row so the scrolling container cannot clip it; replace the primary button's individual focus outline with this row treatment. Keep one row in the tab order using roving `tabindex`: the selected row's primary button has `0`, every other row's has `-1`, and the first row is the initial tab stop.
* Clear the selected-row highlight when the user clicks outside the table or moves focus outside it. Clicking non-focusable page space must also release table focus so the row does not retain its focus highlight. Keep the last active row's primary button as the single row tab stop; highlight it again when focus returns.
* While a row's primary button is focused, `ArrowUp` and `ArrowDown` select and focus the previous or next row in the current displayed order. Stop at the first and last row without wrapping, scroll the destination into view with nearest alignment, and open details only on activation, not arrow navigation. Preserve the selected record through sorting and leave modifier-key shortcuts available to the page. List row navigation and activation keys in the shortcuts popup.
* Open the record in a [details dialog](overlays-and-feedback.md#8-dialogs-and-modals), resolving it by stable identity so sorting cannot change which record opens. Show its current table values plus additional record information in a labelled description list. Preserve the active sort priorities and return focus to the originating row's primary-cell button when the dialog closes.
* Keep a header sticky only inside a vertically scrolling table region. Set its top offset to the region's scroll inset. For a sticky header, use an opaque background matching the surrounding page so scrolling rows do not show through it.
* Make every column sortable and put a native button inside every column header, including status and error rate. Support pointer click, `Enter`, and `Space` through native button behavior. Sort ordinary text alphabetically without case sensitivity; sort numeric values by their number, preserving decimals and ignoring thousands separators and display units. Keep unavailable numeric values after real measurements in both directions; use the raw value when display formatting changes it.
* Sort status columns by explicit health severity: good/healthy first, caution/degraded next, and danger/error last in ascending order; reverse these ranked states for descending order. Use the status's semantic data rather than its label or rendered color. Statuses without a health severity, such as simulated or unknown states, follow the ranked states in both directions. Treat equal severity as a tie so later sort priorities can order rows within each severity group.
* Support sorting by any number of columns without a modifier key. Activating an unsorted column appends it to the sort order in ascending direction. Compare rows by priority: use the second column only when the first ties, the third only when the first two tie, and so on. Preserve the original row order when all active values tie. Include repeated values across multiple columns in a complete reference so secondary and later priorities have a visible effect.
* Cycle each column through ascending, descending, and unsorted. Changing its direction preserves its priority. The third activation removes only that column, keeps the remaining sort directions, and renumbers their priorities consecutively. Re-adding a removed column puts it last. Restore the original row order when no sort columns remain.
* Show Lucide `ArrowUp` for ascending or `ArrowDown` for descending beside each sorted header label, followed by its priority number starting at `1`. Place the arrow-and-priority group after left-aligned labels and before right-aligned labels so the reserved space does not offset a label from its data. Set the number in 11px neutral `--mono` text with tabular numerals and a 4px gap after the arrow. Hide both arrow and number on unsorted headers. Reserve indicator space for the table's maximum possible priority so changing sort state does not shift column widths.
* Set `aria-sort="ascending"` or `descending` only on the highest-priority `<th>` and omit it from the other headers. Give each sort button an associated accessible description containing its direction and priority, such as `Sort priority 2 of 3, descending`, or `Unsorted` when inactive. Hide the visual arrow and priority from assistive technology. Update the row order, indicators, and accessible descriptions together after each sort.
* Keep routine cell text neutral. Put semantic color only inside a status badge or on a threshold-breaching value that also has a textual status.
* For loading, keep column widths stable and set `aria-busy="true"` on the table region. For empty results, render one neutral message that states no records match and include a filter-reset action when filters are active.

## 7. Charts and Data Graphics

* Keep the chart container borderless and transparent so the plot sits on the surrounding page background.
* Render line and area charts as SVG with a responsive width, a 200px default plot height, neutral `--line` gridlines, and 11px `--mono` axis labels in `--muted`. Size the SVG coordinate system to its rendered dimensions so resizing does not stretch labels or misplace pointer inspection.
* Keep one source of timestamped numeric samples for the preview, explorer, statistics, exact-data table, and CSV. Treat missing series values as unavailable, preserve gaps, and never replace missing measurements with zero or invent intermediate samples.
* Include units in axis titles or every applicable tick label. Do not require the surrounding prose to identify a unit.
* Use semantic color only to distinguish real series or provenance. Pair each series color with a unique solid, dashed, or dotted stroke and, when points are selectable, a distinct marker shape.
* Omit a standalone legend above the chart. Name the series in hover readouts and explorer controls, where the labels identify the values or visibility choices.
* On pointer hover, snap to the nearest timestamp in the displayed range and show a vertical crosshair, series markers, and a neutral tooltip with the exact time, series names, values, units, and forecast-minus-observed delta where both values exist. Clamp inspection to the endpoints and keep the tooltip inside the plot. Hide it on pointer exit or blur unless a sample is pinned in the explorer.
* Give the preview an accessible name and concise summary, and make the plot itself a native button that opens its explorer on click, `Enter`, or `Space`. Offer the same sample inspection with `ArrowLeft`, `ArrowRight`, `Home`, and `End`, without wrapping; announce keyboard inspection politely. Do not put a data-table toggle or standalone inspection button below the preview.
* Open a [native modal dialog](overlays-and-feedback.md#8-dialogs-and-modals) at the inspected sample. For the chart explorer, use up to 1120px width and 840px height with 24px viewport clearance, an internally scrolling body, and a persistent export footer. Keep its height stable across view changes and use neutral scrollbars matching the dialog surface. At 600px and below, use 12px viewport clearance; stack the plot, controls, and range fields as needed. Render its plot at 300px high, or 240px on narrow screens. Trap focus and return it to the preview when the dialog closes.
* Provide working `Chart` and `Exact data` tabs with roving tab stops and arrow-key, `Home`, and `End` navigation. Keep the exact-data table inside the dialog and apply the table sorting and alignment rules above. Use an opaque header matching the dialog surface when the data region scrolls vertically.
* Include full-range and shorter-range presets, labeled start/end sliders with exact time readouts and `aria-valuetext`, zoom in/out, earlier/later panning, and reset. Use inclusive endpoints, retain at least two timestamps, clamp zoom and pan to the dataset, and disable controls at their limits. Zoom around the inspected sample and preserve the range width while panning.
* Include named series visibility controls, line/area display, a zero-based or fitted Y axis, gridlines, sample markers, and an optional target line with a labeled numeric value and inline validation. Keep at least one series visible. Show an explicit empty state if the selected series has no measurements in the displayed range. Display controls affect the plot; the exact-data table retains all series in the selected range.
* In the explorer, clicking a sample or pressing `Enter` or `Space` pins its readout. Provide an `Unpin sample` action. Keep keyboard inspection available while pinned, and clear a pin when its sample leaves the selected range. Support `+`/`-` to zoom and `Shift+ArrowLeft`/`Shift+ArrowRight` to pan while the plot is focused; list chart shortcuts in the page's shortcuts popup.
* Show neutral summary statistics for the selected range, including observed mean and peak, forecast mean, and mean forecast delta. Exclude unavailable values from averages and compute differences only for paired timestamps. Reset restores the full range, default display controls, and original data-table order. Preserve explorer settings across dismissal, bringing a newly clicked sample into view on reopening.
* Provide CSV export for the selected range in its current table order and a clearly labeled full-dataset option in original time order. Export UTC ISO timestamps, raw numeric values, and the defined delta; represent missing values as empty fields, escape CSV fields correctly, and include column headers and the covered time range in the filename. Keep export scope distinct from plot visibility settings. Show operation-specific feedback in a polite status region inside the dialog so it remains visible while the modal is open.
* Do not encode observed and modeled data with color alone. Use `--accent` with a solid stroke for observed data and `--derived` with a dashed stroke for modeled data by default.

## 11. Metrics, Cards, and Panels

* For a metric group, render only a metric label and value. Put required units, scope, source, or time range into the label or value.
* Do not render a descriptive or supporting subline beneath the value.
* Keep each metric group transparent, borderless, shadowless, and without container padding. Do not use a card background to separate neighboring metrics.
* Lay out three metrics as equal columns with a 32px gap. At 600px and below, use one column with a 24px gap.
* Set metric labels in `--mono` at 12px, uppercase, letter-spacing 0.08em, and `--muted`. Set metric values at 26px, weight 700, line-height 1, `--muted`, and tabular numerals. Let size and weight establish hierarchy; do not use `--ink-strong` for large metric values.
* Add a bordered or filled card only for a real interactive, independently stateful, draggable, selectable, collapsible, or semantically bounded object. Do not add one for page-section separation.
* When a real card boundary is required, use `--surface`, a 1px `--line` border, 6px radius, and no shadow unless the card is temporarily elevated during drag.

## 13. Color Semantics

* Add a `Color Semantics` section to every complete component reference. Show every shared color token as a swatch with its exact token name, one short usage label, and both dark- and light-theme values; do not rely on a prose introduction to explain the palette.
* Include `--canvas`, `--surface`, `--surface-raised`, `--ink`, `--ink-strong`, `--muted`, `--faint`, `--line`, `--line-strong`, `--action-primary`, `--action-primary-hover`, `--control-selected`, `--control-selected-hover`, `--focus`, `--accent`, `--good`, `--caution`, `--danger`, and `--derived`. Show each semantic token's soft tint in the same swatch and label the tint opacity beside each theme value.
* Lay tokens out in a responsive grid with a 240px minimum column width, 32px column gaps, and 24px row gaps. At narrow widths, collapse to one column without horizontal overflow.
* Build each token as a 44px swatch beside a text block. Set the token name in 12px semibold `--mono`, the usage label in 13px `--muted`, and theme values in 10.5px `--faint` monospace text that may wrap only between complete values.
* Keep every swatch and soft-tint region borderless, dividerless, outlineless, and shadowless; the color fill itself provides the shape. Use a 6px default radius, keep good swatches at 6px, caution swatches at 4px, and danger swatches at 0px; never round a red swatch.
* Use `Viewport background`, `Controls and bounded surfaces`, `Overlays and active rows`, `Body text and data values`, `Headings and selected values`, `Secondary metadata and labels`, `Placeholders and inactive icons`, `Borders and row dividers`, `Active and overlay boundaries`, `Primary action fill`, `Hovered primary action fill`, `Selected control fill`, `Hovered selected control fill`, `Keyboard focus only`, `Observed data`, `Healthy or successful`, `Warning or degraded`, `Error, outage, or destructive`, and `Estimated, modeled, or synthetic` as the corresponding usage labels in token order.
