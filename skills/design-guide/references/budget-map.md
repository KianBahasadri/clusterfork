# Budget Map

## 14. Shared Time and Limit Plane

Use this component to see which of several budgets, quotas, or capacities is approaching its own ceiling, and where each is forecast to finish. It works best with two to six items sharing the same period. Each item must have a positive limit and use the same unit for its history, current value, forecast, and limit. Different items may have different units: the shared coordinate is percentage of that item's limit, never a sum of unrelated amounts. Use a table when exact lookup is the main task; use the map when relative pressure and trajectory should be visible together.

The [runnable examples](../assets/component-reference/index.html#budget-map) use illustrative budgets for AWS, Azure, Blacksmith, GitHub Actions, and OpenRouter. The first map keeps every forecast within its limit; the second includes forecast overruns; the third mixes large overruns with within-limit peers to demonstrate scale compression and repeated 100% markers. Each map identifies its scenario and sample data in its accessible name and description. Amounts and limits are fictional. The map draws supplied forecasts; its details dialog computes usage rates and alternative projections from the supplied history. It does not fetch data.

## Anatomy and Geometry

- Draw one transparent, borderless SVG containing a shared time/usage plane. Time advances from the left period-start edge to the right period-end edge, and usage increases from the near bottom edge toward the far top edge. Keep the front and back edges horizontal, logos upright, and shared coordinates for every item. Do not replace the plane with separate per-item charts or place it inside a decorative card.
- The default fixed camera uses near-edge width `W`, visible depth `D = 0.34W`, and perspective factor `0.4`. For normalized time `t` and normalized usage `u = percentage / fitted maximum`, project `x = centerX + (t - 0.5)W / (1 + 0.4u)` and `y = bottomY - 1.4uD / (1 + 0.4u)`. The far edge is about 71.4% as wide as the near edge; time gridlines converge and usage gridlines tighten toward it. The catalog enables the separate dynamic projection described below.
- Normalize each raw amount as `amount / item.limit * 100`. The period start is time zero; period end is time one. Put the current markers on the shared `asOf` line and forecasts on the shared period-end edge. Keep every marker centered on its actual coordinate; do not spread coincident values apart. Inspection brings the selected item's trail and logo to the foreground.
- Start the usage scale at zero with a 100% maximum when all values fit. If any historical, current, or forecast percentage exceeds 100%, expand the maximum to that largest supplied percentage without rounding up or adding extra headroom. Recalculate on data updates and return to 100% when all supplied values fit again. Keep overruns visible past the 100% limit; do not clamp them to the boundary. Include the fitted maximum and exact period in the accessible description.
- Draw usage gridlines every 25 percentage points across the scale up through the third red bar (300%), including 125%, 150%, and subsequent steps inside the red region when they fit. After the third red bar, remove intermediate 25% ticks between the red bars, drawing only the subsequent 100% markers (400%, 500%, etc.). Draw the outer edge at the exact fitted maximum as well; do not duplicate it when the maximum is already a 25% step. Keep gridlines neutral except for the 100% danger boundary and each subsequent 100% overage marker (every fourth bar after the first red bar: 200%, 300%, etc.), which repeat the 1.5px `--danger` stroke at 40% opacity to make large overages easier to count. Render that boundary as a 1.5px `--danger` stroke at 40% opacity and the angular region beyond it in `--danger-soft` at 35% element opacity, multiplying the soft token's existing alpha. Keep this reference area subdued even when an item overruns. Give the near bottom edge a slightly stronger neutral stroke. Mark the current time with a neutral dashed line. A faint dotted line from period-start zero to period-end 100% shows even consumption pace.
- Draw observed history as solid `--accent` trails with small sample dots. Use each service's supplied logo for its current marker, preserving its recognizable vector silhouette and brand colors. Keep logos upright in screen space, with a 22px size on wide containers and 16px below 480px; wide marks may use 1.2 times that width while preserving aspect ratio. Brand colors identify the provider and do not change the chart's data/state colors. Use a filled neutral-series marker only when an item has no registered logo.
- Draw supplied forecasts as dashed `--derived` connectors and small solid end markers (no hollow center). Forecasts below 50% of the limit omit both the connector and endpoint; retain their supplied values in accessible summaries, details, and export. At or above 50%, show both when a current value is available; without a current value, show only the endpoint. Change only the part of a forecast beyond 100% to `--danger`. Do not fabricate observations, extrapolate a forecast for the map, or connect across an explicit null history sample. A single observation remains a point. Use small solid circles for forecasts at or below the warning threshold, a 2px-radius square for near-limit forecasts, and a sharp square for overruns. Current overruns take precedence over a lower forecast.
- Apply the dark cockpit treatment to each complete item group, including its trails, sample dots, logo, and endpoint. Use 45% opacity for a known forecast at or below 100% while current usage is not over the limit; near-limit forecasts retain their caution shape and color at this reduced opacity. Keep current or forecast overruns at full opacity. A missing forecast retains neutral status and full opacity rather than appearing confirmed within limit. Multiply the resting opacity by 60% for stale items. Hover or keyboard inspection restores the selected group to full opacity and dims other groups to 20%; clearing inspection restores their resting treatment. Preserve provenance colors, stroke patterns, and status geometry in every contrast state.
- Keep the populated map free of persistent text: no axis labels, dates, values, item names, status captions, leader lines, or legend. Names, exact values, units, dates, and status text appear in hover/keyboard readouts, the details dialog, and the accessible description. Use `--mono` at 11px for readout dates and the shared text styles for inspection details.
- Omit the dataset-title, date-range, and sample-data header. Use the dataset title for the plot's accessible name and a screen-reader-only dialog heading. Center the plane, cap its width at 720px for the fixed camera, leave 16px clearance around it (8px below 480px), and derive height from the projection ratio. Retain vertical scrolling and zoom. Each example has its own inspection, dialog, sorting, and export state.

### Dynamic Projection and Catalog Controls

- To reproduce the catalog, pass `dynamicPerspective: true`. Use `W = max(240px, container width) - 2 × clearance`, with no 720px plane cap, and `D = round(0.90W)`. A fitted maximum `M <= 100` uses perspective `p = 0`, giving a rectangular plane. For `100 < M <= 132`, use `p = (M - 100) / 32 * 0.4 * tiltIntensity`; above 132, use `p = (0.4 + 0.21 * min(5, (M - 132) / 100)) * tiltIntensity`. Project the transformed usage coordinate with `x = centerX + (t - 0.5)W / (1 + pu)` and `y = bottomY - D * u * (1 + p) / (1 + pu)`.
- Dynamic usage spacing combines baseline compression with overage severity: `k = compressionIntensity + severityIntensity * 0.6 * min(5, max(0, (M - 100) / 100))`. Use the `point()` mapping in [budget-map-plot.js](../assets/component-reference/components/budget-map-plot.js) to compress the upper overage intervals while retaining the actual percentage coordinates. With `compressNonOverage: false`, usage at or below 100% maps linearly within its portion of the plane before perspective projection; enabling it applies the nonlinear compression across the whole scale. Keep the fixed camera's linear usage mapping when dynamic perspective is off.
- Above 900px, place the three maps in equal columns with an 8px gap. At 900px and below, stack them with 32px gaps. Put the shared controls above this grid with 8px below the toolbar; they update all three maps together. The catalog enables dynamic perspective and leaves `dynamicCamera` off.
- Use the [precision slider treatment](controls-and-forms.md#4-selection-controls) for `Overage tilt`, `Bar compression`, and `Overage severity`. Their range is 0–1000%, step 5%, with initial values 20%, 0%, and 80%; divide the displayed percentage by 100 before passing the corresponding option. Use 210px-wide controls, shrinking to the available width, with 12px row and 20px column gaps. At 600px and below or with a coarse pointer, use full-width controls capped at 240px. Include a `Compress non-overages` switch, initially off, with a 44px interaction height. These controls belong to the catalog wrapper; the reusable map does not create them.

## Data and States

The constructor accepts one object with `title`, ISO `start`, `end`, and `asOf` timestamps, optional `sample`, optional `warningAt` (default 75 percent), and an `items` array. Use `start <= asOf < end`; a monthly period can end at midnight on the first of the following month. `warningAt` must be greater than zero and less than 100.

Each item has a stable string `id`, a `label` for inspection and accessibility, a `unit` string, a positive numeric `limit`, numeric or null `current` and `forecast` values, optional `logo` registry key, optional `stale`, and a `history` array of `{ at, value }`. Historical timestamps must be unique and fall inside `[start, asOf)`; input order is normalized chronologically. Use explicit null samples to mark gaps. Amounts must be finite and non-negative. An unavailable amount is null, including in exported data; zero is a real measurement.

In inspection and accessible descriptions, forecasts above 100% say `Forecast over limit`; forecasts surpassing `warningAt` through 100% say `Near limit`; lower forecasts say `Within limit`. A current amount above 100% says `Over limit now`. Missing forecasts say `No forecast`, and missing current and forecast values say `Unavailable`. Retained stale data is dimmed and labelled `Stale` in inspection. An entirely empty or unavailable dataset has a visible message instead of appearing to be a healthy empty map; individual unavailable sources are named in the accessible description and details dialog.

## Usage Rates and Forecast Comparison

Use the details dialog's analysis for cumulative consumption within the shared period. Keep the supplied forecast as the map's endpoint and health-status source; alternative scenarios are labelled calculations confined to the dialog. Never replace the supplied forecast, expand the map's scale with these scenarios, or insert synthetic observations into history or raw export.

- Compute period-average, trailing 7-day, and trailing 3-day rates as `(current − usage at window start) / window duration in days`. Use exact elapsed UTC time with 24-hour days, including partial days. The period average requires an observation at the period start and subtracts its actual value, even when non-zero; never assume an absent baseline is zero.
- A trailing window must fit entirely inside the period. Use an exact boundary observation when available; otherwise linearly interpolate the boundary between its immediately adjacent supplied observations, labelling both the rate and the scenario `Interpolated window start`. Do not extrapolate a missing starting observation or cross an explicit null sample. A missing current reading, gap, or decrease anywhere in the required window makes that rate unavailable with a concise reason. Decreasing usage can reflect resets or adjustments and must not silently become a negative consumption forecast. A valid zero rate stays zero.
- Show current headroom (`limit − current`) and the sustainable daily rate (`max(0, headroom) / remaining days`). Compare the 3-day rate with the period average as a percentage change; show an unavailable dash when the average is zero. Required reduction is `max(0, 1 − sustainable rate / 3-day rate)` expressed as a percentage, or zero when the available 3-day rate is zero. Preserve negative headroom for an existing overrun.
- Compare four scenarios: the supplied forecast, period-average continuation, 7-day-average continuation, and 3-day-average continuation. Each computed total is `current + window rate × remaining days`. The supplied forecast's displayed daily rate is its **implied** remaining-period rate, `(forecast − current) / remaining days`, not an assertion about the provider's forecasting algorithm. Keep the supplied total available even when a missing current value prevents calculating that implied rate.
- For every scenario, show its basis, rate per day, period-end amount, percentage of limit, forecast headroom, and estimated limit date. Estimate the crossing from the current amount at that scenario's constant daily rate. Show `Already reached` at or above the current limit, `Not reached` for a non-positive rate below the limit, `After period` when a positive rate reaches the limit beyond the period, or a UTC date and time for a crossing within the period (including exactly at its end). Missing calculations use neutral dashes; arithmetic overflow is unavailable. Forecast headroom remains signed.
- Use at most two decimal places for calculated rates and amounts, one for percentages, and minute precision for estimated dates. Keep unrounded numbers for calculations and sorting. Name units beside the rate values and in the comparison heading and accessible caption. Date windows and `Calculation notes` expose formulas, interpolation, rounding, and constant-rate assumptions; do not invent confidence intervals or imply that these scenarios capture seasonality. Stale analysis remains anchored to the supplied `asOf` timestamp and inherits the visible stale label.

## Inspection and Exact Data

- Make the interactive preview a native button. Hover inspects the nearest supplied observation, current marker, or forecast endpoint, emphasizes that item's entire trail, and shows the full item name, exact amount and unit, percentage, UTC date, and status. Keep the neutral readout within the plot. Clear it on pointer exit, blur, or Escape.
- Left/Right move through items in input order; Home/End reach the endpoints without wrapping. Announce keyboard inspection politely. Preserve page modifier shortcuts. Enter, Space, or tapping the map opens the selected item's details in a labelled native dialog.
- In the dialog, offer working item selection, a `Budget position` column and a `Usage rates` column, then a full-width `Forecast comparison` table. Show the period, elapsed days, and remaining days beneath the selected item and status. Keep formulas behind a keyboard-operable native `Calculation notes` disclosure. Put the complete supplied-data table behind `Show exact data` inside this dialog. Both tables support the shared sort cycle and multiple priorities independently; retain sort priorities when switching items or updating the data. Confine wide tables to named, keyboard-scrollable regions. The exact-data table's header is opaque and sticky within its vertical scroll region.
- Use `--accent` for observed/current readings and rates computed from exact observed boundaries. Use `--derived` for interpolated rates, sustainable rate, rate comparisons, required reduction, and all forecast values, percentages, headroom, and estimated dates. Apply provenance colors to the summary's labels, dates, values, and units. In the exact-data table, color each sample's timestamp, kind, available value, unit, and percentage according to its provenance. Keep reference limits, item names, headers, method descriptions, and missing-value dashes neutral. Preserve the separate caution/danger treatment of the budget's health status. Retain explicit current, observed, forecast, and interpolation wording so color is not the only distinction; do not add a legend.
- Size the dialog to at most 880px wide in both summary and exact-data views, always keeping 12px viewport clearance. Use one header row for the wrapping service picker and the close control, separated by 8px; align the close control with the first picker row. Keep this header outside the scrolling body. Omit a separate title/close row and footer. Lay out the two transparent summary groups as equal columns with a 32px gap, using 13.5px labels and right-aligned monospaced values; stack them at 700px and below with a 24px gap. Use the whole available width, with 20px above the groups and 24px before the forecast comparison. Keep the comparison table compact with 8px cell padding and 12px sortable headers. Put `Show exact data` and `Export all data CSV` together below the calculation disclosure, with an 8px gap and wrapping when needed.
- `Export all data CSV` always exports every item's supplied history, current amount, and forecast in input-item/chronological order, independent of the inspected item and table sort. Include UTC timestamps, raw amounts, units, limits, percentages, freshness, and headers; leave unavailable values empty and escape CSV fields. Include the period in the filename and announce export completion below the action row. Leave that feedback region empty with no reserved space on opening; omit a default dataset-description caption.
- Trap dialog focus, close on Escape or backdrop activation, and restore focus to the map. Keep the modal's outer border at zero. Use the shared dialog surface, backdrop, typography, controls, and responsive touch targets. Map interaction shortcuts belong in the page's shortcut popup.
- For a passive desktop readout, set `interactive: false`. Render the same map and accessible data summary without clickable controls or a dialog. The visual structure does not depend on hover.

## Copying the Implementation

Copy `budget-map-model.js`, `budget-map-plot.js`, `budget-map.js`, and `budget-map.css` from `assets/component-reference/components/`, together with the shared tokens/base styles. Load the model first, then the plot and controller. Interactive use also needs the existing dialog/button/table styles and Lucide `X`/sort-arrow symbols; load `table-sorting.js` after the model and before the controller. The model creates `window.ComponentReference` if needed; no catalog element IDs or sample dataset are required.

For provider marks, also copy `budget-map-logos.js` and load it after the model and before initialization. It registers `aws`, `azure`, `blacksmith`, `github-actions`, and `openrouter`, using the vector paths from the original Conky billing map (`conky-linear-HUP`, revision `a8152dd`). The AWS mark retains that map's compact smile treatment. The brands retain ownership of their marks. To supply other logos, pass `options.logos` as a registry whose entries contain SVG `viewBox`, positive width/height `ratio`, and a `paths` array of SVG path attributes. Use verified vector assets for each service's identity. Unknown or omitted logo keys use the generic current marker.

```html
<div id="spend-map"></div>
<script>
  var map = ComponentReference.createBudgetMap(
    document.getElementById("spend-map"),
    {
      title: "Compute budget", start: "2026-09-01T00:00:00Z",
      end: "2026-10-01T00:00:00Z", asOf: "2026-09-16T00:00:00Z",
      items: [{
        id: "compute", label: "Compute", unit: "USD", limit: 10000,
        current: 7200, forecast: 13200,
        history: [
          { at: "2026-09-01T00:00:00Z", value: 0 },
          { at: "2026-09-09T00:00:00Z", value: 3500 },
          { at: "2026-09-13T00:00:00Z", value: 5500 }
        ]
      }]
    },
    { dynamicPerspective: true }
  );
</script>
```

`createBudgetMap(root, data, options)` owns only the supplied root's contents. Each instance has independent selection, dialog IDs, sort state, and resize observation. Call `map.update(nextData)` with another complete dataset; invalid updates leave the existing model unchanged. Use `map.setOption(key, value)` to redraw projection settings on a mounted instance; choose interaction mode and the logo registry at construction. Call `map.destroy()` before removing or remounting its root to disconnect the observer and dispose of its dialog.

| Option | Default | Effect |
| --- | --- | --- |
| `interactive` | `true` | Set `false` for a passive map without controls or a dialog |
| `dynamicPerspective` | `false` | Enable the catalog's taller plane, overage tilt, and compression |
| `tiltIntensity` | `0.2` | Scale the overage-dependent perspective factor |
| `compressionIntensity` | `0` | Set the baseline compression strength in dynamic mode |
| `severityIntensity` | `0.8` | Scale the additional compression from overage severity |
| `compressNonOverage` | `false` | Also compress the at-or-below-limit portion in dynamic mode |
| `dynamicCamera` | `false` | Move the visible base to 100% when all available current and forecast values are at or above that limit, clipping earlier history below it |

`budget-map-example.js` supplies the catalog's fictional data, mounts, and control bindings; replace it in another product. Copying its toolbar also requires the shared form-control markup/styles and slider initialization described in Controls and Forms.
